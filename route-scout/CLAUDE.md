# route-scout — 作業ルールと現状

**mono-labo 直下の CLAUDE.md も必ず読むこと。** プッシュ前の fetch、ファイル丸ごと上書きの禁止、
触ってはいけないファイルはそちらに書いてある。ここは route-scout 固有のこと。

ブランチ: `claude/tractor-navigation-app-3455pt`

## これは何か

出発地と目的地から、**できるだけ幅員の広い道を通るルート**を作り、Google マップに渡す道具。
走行中の案内は Google に任せる。自前のナビではない。使う人はキャンピングトレーラーの牽引者。

**「下見ツール」から作り替えた経緯があるので、古い言い方が残っていたら直すこと。**
当初は「狭い区間を一覧で出す」設計だったが、警告が何十件も並んでも誰も見ないため、
「広い道のルートを作って返す」に変えた。一覧は結論の根拠として添えるだけ。

## すぐ動かす

```
# Windows: route-scout/start-windows.bat をダブルクリック
# それ以外: リポジトリ直下で
python -m http.server 8080 --directory .
```

→ `http://localhost:8080/route-scout/` （`file://` では ES モジュールが動かないので必ず HTTP 経由）

```
node route-scout/test/run.mjs     # 36件。ネットワークにも npm にも依存しない
```

ユーザーの PC は **Windows**。`python3` は存在しないので `python` か `py` を使うこと。

## 最初に確かめること（最重要）

**地理院のベクタタイル（`.pbf`）をブラウザから `fetch` できるか。** ここが全部の前提。

- 画面に「読めませんでした」と出たら、CORS が原因の可能性が高い
- ラスタタイル（`.png`）は姉妹サイト biei-daily の `map.html` が実際に読めている。
  ただしラスタは `<img>`、ベクタは `fetch` なので**別物**。動作実績は根拠にならない
- 読めなければ `proxy/` にタイル中継を足して回避する（Google と違い地理院のキャッシュに制限はない）

## 崩してはいけない設計の前提

- **自前で経路探索しない。** ベクタタイルには道路の接続情報が無く、一方通行・進入禁止も
  入っていない。幅員だけで経路を引くと逆走ルートが出る。経由点を置いて Google に繋がせる
- **通行可否は保証しない。** 電柱・路上駐車・カーブミラーの張り出し・内輪差はデータに無い。
  「ここは見ておいたほうがいい」までしか言えない。免責をUIから外さないこと
- **区分 5（その他）と 6（不明）を「問題なし」と言わない。** 幅員の実測ではないので UNKNOWN 扱い。
  データが無いことを大丈夫と読ませない
- **最近傍だけでスナップしない。** 進行方位が揃った線分を優先する。並走する路地を拾うと
  誤警告だらけになり、一覧が信用されなくなる
- **良くなったときだけ採用する。** 引き直した結果を採点し、改善しなければ捨てる
- **課金の上限を持つ。** `maxRouteCalls` で頭打ち（既定 4 回 + 初回）

## 実データで未検証のこと

このコードはクラウド環境で書かれ、**地理院にも Google にも OSRM にも到達できなかった**
（組織の egress ポリシー）。合成データとブラウザでの通し検証は済んでいるが、以下は全部未確認。

- ベクタタイルの CORS（上記）
- `rnkWidth` の値が牽引の実感と合うか。`bin/probe.mjs --health` で実走で知っている地点を 10 か所
- 進行方向を向いた SV リンクが本当に正しい向きか。10 か所ほど開いて目視
- 遠回りの重み `detourPenaltyPerKm`（既定 100 = 遠回り1km を狭い道100m相当と見る）の妥当性
- Maps URLs の `waypoints` 上限（画面では 9 で切っているが一次ソース未確認）
- Google Routes API のフィールドマスクと SKU の対応（引き継ぎ資料の記載のまま。要確認）
- OSRM 公開デモと Nominatim への実接続

**一次ソースを開けないまま書いた箇所は、コード内コメントにその旨を残してある。**

## 次にやること（順番どおりに）

1. ローカルで開き、**ベクタタイルが読めるか**確かめる。読めなければタイル中継を足す
2. 美瑛周辺の実ルートで、警告の量と妥当性を見る。多すぎたら閾値を詰める
3. **独立したリポジトリ `route-scout` を作って GitHub Pages で公開する。**
   mono-labo には置かない。offgrid-designer / drain-cover-generator / biei-daily と同じ形。
   mono-labo 側にはランディングとリンクだけ置く
4. 公開時は キー不要モード（OSRM 公開デモ）を外し、`proxy/worker.mjs` を Cloudflare Workers に
   置いて Google Routes API に切り替える。`ALLOW_ORIGIN` を公開先に絞ること
